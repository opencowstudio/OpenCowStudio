# Entity Decorator Reference

Options, defaults and validation rules of the `@PgEntity` / `@PgKey` / `@PgColumn`
decorators.

## Imports

```ts
import { PgEntity, PgKey, PgColumn } from '@opencowstudio/pg-core'
import type {
  PgEntityOptions,
  PgKeyOptions,
  PgColumnOptions,
  PgIndexOptions,
  ColumnType,
} from '@opencowstudio/pg-core'
```

## Boolean options

Every boolean option is a plain `boolean`. String forms (`'true'` / `'false'` / `'1'` /
`'0'`) and any other type are rejected with
`Invalid boolean value "<value>" for <context>: expected a boolean.` `undefined` falls
back to the option's default.

## Option defaults

Only `PgColumnOptions.columnType` and `PgIndexOptions.columns` are required. All other
options are optional and defaulted, so omit them unless a different value is required.

## `ColumnType`

```ts
type ColumnType =
  | 'BIGINT'
  | 'DOUBLE'
  | 'BOOLEAN'
  | 'JSON_OBJECT'
  | 'JSON_ARRAY'
  | 'TEXT'
  | 'DATE'
```

## `@PgEntity(options?)` — class decorator

| Option | Type | Default | Meaning |
|---|---|---|---|
| `table` | `string` | snake_case(class name) | Table name |
| `schema` | `string` | `'public'` | Schema name |
| `dbName` | `string` | `'default'` | Key under `databases` in `app.config.yaml` |
| `comment` | `string` | `''` | Table comment |
| `createTableAuto` | `boolean` | `true` | Auto-create the table when absent |
| `addColumnAuto` | `boolean` | `true` | Auto-add columns missing in the database |
| `createIndexAuto` | `boolean` | `true` | Auto-create the declared indexes |
| `indexes` | `PgIndexOptions[]` | `[]` (none) | Table indexes to create, in declaration order |

Blank or whitespace-only strings for `table` / `schema` / `dbName` fall back to their
defaults. The decorator may be called bare (`@PgEntity()`) or with an object literal.

## `PgIndexOptions` — one entry of `@PgEntity({ indexes: [...] })`

| Option | Type | Default | Meaning |
|---|---|---|---|
| `columns` | `string[]` | — (**required**) | Database column names forming the index |
| `unique` | `boolean` | `false` | Whether the index is unique |

There is **no** `@PgIndex` decorator: indexes are declared as an array inside the
`@PgEntity` argument, e.g.
`@PgEntity({ indexes: [{ columns: ['account'], unique: true }] })`.

`columns` is required and must be a non-empty array literal of statically evaluable
strings. A malformed entry (non-array `indexes`, a non-object entry, or a missing / empty
/ non-string `columns`) throws. Each entry is validated as an identifier, but entries are
**not** checked against the entity's declared columns — a typo only surfaces when the
index is created against PostgreSQL.

## `@PgKey(options?)` — property decorator (exactly one per entity)

| Option | Type | Default | Meaning |
|---|---|---|---|
| `generated` | `boolean` | `true` | Key is generated by the database (SERIAL / GENERATED ALWAYS) |
| `comment` | `string` | `''` | Column comment |

There is **no** `column` option: the key's database column is always `id`, regardless of
the property name.

Runtime behaviour: the decorator installs a class-field initializer that throws when a
set key value is not a `string`. Declaring `@PgKey() id!: number` therefore parses fine
but fails at instance initialization. Keep key properties typed as `string`.

The runtime expects the key property to be `id`, so name the key field `id`.

## `@PgColumn(options?)` — property decorator

| Option | Type | Default | Meaning |
|---|---|---|---|
| `columnType` | `ColumnType` | — (**required**) | Logical SQL column type |
| `column` | `string` | snake_case(property name) | Column name |
| `comment` | `string` | `''` | Column comment |

`columnType` is mandatory: `@PgColumn()` with no argument throws
`Missing required columnType for column <property> on <Class>`.

## Literal evaluation rules

Decorator arguments are evaluated from source text, so only these forms are supported:

- String, numeric, boolean, `null`, `undefined` literals; single-quoted and
  no-substitution template literals.
- Arrays and object literals (implicit keys, quoted keys, computed keys that reduce to a
  literal).
- Object spread where the spread operand is itself statically evaluable.
- Identifiers resolving to a keyword or to a **top-level `const` / `let` / `var` declared
  in the same file** whose initializer is itself evaluable.
- Parenthesised, `as` and non-null-wrapped expressions; unary minus on a numeric literal.

Anything else throws a position-aware error, for example:

- `Cannot evaluate decorator expression of kind CallExpression at <file>:<line>:<col>.`
- `Cannot resolve identifier "X" used in a decorator at <file>:<line>:<col>. Use a literal or a locally-declared constant.`

Consequences: importing a shared constant (`import { SCHEMA } from './constants'`) or
calling a helper (`@PgEntity({ table: buildName('user') })`) makes the entity
unreadable.

An entity that breaks a rule is skipped with `Skipping entity "<Name>": <error>` rather
than failing the build.

## Exact error messages

| Situation | Message |
|---|---|
| No `@PgKey` | `Entity "<Name>" declares no @PgKey field; an entity must declare exactly one @PgKey.` |
| Multiple `@PgKey` | `Entity declares multiple @PgKey fields (<a>, <b>); an entity must declare exactly one @PgKey.` |
| Missing `columnType` | `Missing required columnType for column <prop> on <Name>. Expected one of: BIGINT, DOUBLE, BOOLEAN, JSON_OBJECT, JSON_ARRAY, TEXT, DATE.` |
| Unknown `columnType` | `Invalid columnType "<value>" for column <prop> on <Name>. Expected one of: ...` |
| Bad identifier | `Invalid <kind> "<value>": must match /^[a-zA-Z0-9_]+$/ (alphanumeric and underscore only). Context: <context>` |
| Bad boolean | `Invalid boolean value "<value>" for <context>: expected a boolean.` |
| `indexes` not an array | `Invalid "indexes" option for entity <Name>: expected an array of index definitions.` |
| `indexes` entry not an object | `Invalid entity <Name> index #<n>: expected an object literal with a "columns" array.` |
| `indexes` entry has bad `columns` | `Invalid entity <Name> index #<n>: "columns" must be a non-empty array of column names.` |
| Non-object decorator argument | `@<Decorator> expects an object-literal argument at <file>:<line>:<col>.` |
| Unsupported expression | `Cannot evaluate decorator expression of kind <Kind> at <file>:<line>:<col>.` |
